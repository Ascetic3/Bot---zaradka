# Бот клуба «Магия утра»

Telegram-бот клуба «Магия утра» на Node.js и grammY. Данные участников хранятся в SQLite.

## Требования

Установите Node.js (LTS). В PowerShell используйте `npm.cmd`, если команда `npm` заблокирована.

## Настройка

1. В этой папке скопируйте пример настроек:

   ```powershell
   Copy-Item .env.example .env
   ```

2. Откройте `.env` и замените значение `BOT_TOKEN` на токен, выданный BotFather. Не публикуйте этот файл и не отправляйте токен в чат.
3. Установите зависимости:

   ```powershell
   npm.cmd install
   ```

## Запуск

```powershell
npm.cmd start
```

Пока процесс работает, откройте своего бота в Telegram и отправьте `/start`. Он ответит: «Добро пожаловать в клуб „Магия утра“!».

Для остановки нажмите `Ctrl+C` в терминале.

## Резервное копирование SQLite

Ручную копию можно создать в любой момент, в том числе пока бот работает:

```powershell
npm.cmd run backup
```

Команда использует тот же файл базы, который настроен через `DB_PATH` (или `data/club.sqlite`, если `DB_PATH` пуст). Перед открытием база проверяется на существование, поэтому команда не создаст новую пустую базу вместо отсутствующей. Для копирования используется встроенный SQLite-механизм `better-sqlite3.backup()`, который корректно учитывает режим WAL. После создания копия проверяется командой `PRAGMA integrity_check` и наличием таблиц участников, аккаунтов, администраторов и черновиков. Если проверка не пройдена, копия не считается успешной.

### Настройки

Добавьте нужные значения в свой локальный `.env`:

```env
BACKUP_DIR=
BACKUP_INTERVAL_HOURS=24
BACKUP_RETENTION_COUNT=14
BACKUP_AUTO_ENABLED=true
```

- `BACKUP_DIR` задаёт папку резервных копий. Если оставить пустым, Windows использует приватную системную папку `%LOCALAPPDATA%\MagicMorningBot\backups`; на других системах — `~/.local/share/MagicMorningBot/backups`.
- `BACKUP_INTERVAL_HOURS` задаёт интервал автоматических копий. По умолчанию — 24 часа.
- `BACKUP_RETENTION_COUNT` задаёт число сохраняемых исправных копий. По умолчанию — 14.
- `BACKUP_AUTO_ENABLED=false` отключает автоматическое копирование, например на компьютере разработчика. Значение по умолчанию — включено.

Автоматическое резервирование запускается после подключения бота к Telegram: бот создаёт первую копию, затем повторяет операцию с заданным интервалом. Копии создаются только пока работает процесс бота. Если компьютер или бот выключен, новые копии не создаются. Ошибки копирования записываются в журнал только как безопасный технический тип ошибки, без текста анкет.

По умолчанию резервные файлы хранятся вне папки проекта. Если вы укажете `BACKUP_DIR` внутри проекта, файлы SQLite и папки `backups` игнорируются Git. Доступ к папке резервных копий должен иметь только владелец клуба или уполномоченный оператор: в копиях содержатся персональные данные.

### Ручное восстановление

Восстановление автоматически не выполняется. Перед заменой рабочей базы остановите бот и убедитесь, что выбрали исправную резервную копию.

1. Пока бот ещё работает, попробуйте сохранить текущее состояние командой `npm.cmd run backup`. Если база повреждена и команда завершается ошибкой, после остановки бота сохраните вручную текущий файл базы и все имеющиеся рядом файлы `-wal`, `-shm` и `-journal` в отдельную папку восстановления.
2. Остановите бот в его терминале сочетанием `Ctrl+C` и дождитесь завершения процесса. Не заменяйте базу, пока бот работает.
3. Выберите резервный файл `magic-morning-....sqlite`. Проверьте его целостность в PowerShell, подставив полный путь к выбранной копии:

   ```powershell
   node -e "const D=require('better-sqlite3'); const d=new D(process.argv[1],{readonly:true,fileMustExist:true}); console.log(d.pragma('integrity_check')); d.close()" "C:\путь\к\копии.sqlite"
   ```

   Результат должен содержать `ok`. Созданные этой программой копии дополнительно проверяются на наличие всех четырёх таблиц до того, как команда объявит успех.
4. Сохраните нынешний основной файл базы и его WAL/SHM/journal-файлы в отдельную резервную папку. Не удаляйте их: после остановки процесса их можно переместить как единый комплект.
5. Скопируйте выбранную проверенную `.sqlite`-копию на путь рабочей базы. Резервная копия представляет собой самостоятельную базу; не переносите рядом с ней старые `-wal` или `-shm` от заменяемой базы.
6. Запустите бота командой `npm.cmd start`. Проверьте `/start`, личную анкету и административную статистику. Если возникнет проблема, остановите бота и верните сохранённый комплект исходной базы.

Не выполняйте восстановление настоящей базы, пока отдельно не подтвердите это действие и не убедитесь, что сохранена исходная база.

### Политика обработки персональных данных

Перед запуском регистрации укажите в локальном `.env` действительную ссылку на политику:

```env
PRIVACY_POLICY_URL=https://ваш-домен/политика
```

Пример URL выше нужно заменить адресом утверждённой политики. Если переменная пустая или отсутствует, регистрация не начинает сбор анкеты. Не добавляйте секреты в `.env.example`.

### Первоначальная настройка владельца и администраторов

В локальном `.env` укажите Telegram ID владельца клуба:

```env
OWNER_TELEGRAM_ID=123456789
```

Замените пример чисел на фактический Telegram ID владельца. Имя пользователя (username) не используется. Если переменная не задана, никто автоматически не получает административные права. Владелец открывает `/admin` в личном чате с ботом и через «⚙️ Управление администраторами» может добавить или удалить администраторов по их Telegram ID.

## Демонстрация административной панели

Для демонстрации используется отдельная база `data/demo.sqlite`. Генератор создаёт 150 вымышленных участников, разнообразные города и даты за последние 120 дней. Почта оканчивается на зарезервированный домен `.example`, телефоны имеют синтетический код `+999`, а связанные идентификаторы начинаются с `DEMO-`. Эти данные нельзя использовать для звонков, писем или отправки сообщений. Телефоны остаются неподтверждёнными, а согласие не отмечается.

Перед запуском убедитесь, что в `.env` настроен ваш настоящий `OWNER_TELEGRAM_ID`. Перед повторным наполнением остановите демо-бот, если он сейчас запущен. Команда наполнения использует штатное назначение владельца и откажется перезаписывать базу с другим владельцем или незнакомыми данными.

В PowerShell из папки проекта:

```powershell
npm.cmd run demo:seed
npm.cmd run demo:start
```

Остановите обычный экземпляр бота перед `demo:start`: Telegram не допускает одновременную работу двух экземпляров с одним токеном. В демонстрационном процессе задан путь `data/demo.sqlite`, включён видимый баннер в `/admin`, Excel-файл получает префикс `ДЕМО_`, а автоматическое резервирование выключено. Это также не позволяет копировать демо-базу в папку резервных копий рабочей базы.

Чтобы вернуться к обычной базе, остановите демо-бот сочетанием `Ctrl+C` и запустите `npm.cmd start`. Обычный запуск использует `DB_PATH` из `.env`, а если он пуст — `data/club.sqlite`. Не запускайте оба процесса одновременно с одним Telegram-токеном.

Повторный `demo:seed` проверяет метку генератора и содержимое базы. Если набор уже цел, команда ничего не добавляет; если в файле обнаружены неизвестные или изменённые записи, заполнение прекращается без их удаления или перезаписи. Не удаляйте `data/demo.sqlite`, если в ней появились нужные вам демонстрационные изменения.
